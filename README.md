## הוראות הרצה

### גרסה פגיעה

פתחו טרמינל ונווטו לגרסה הפגיעה:
```bash
cd Vulnerable_Version
python vulnerable_app.py
```

פתחו דפדפן וגשו לכתובת:
```
http://127.0.0.1:5000
```

צרו חשבון חדש — ניתן ליצור חשבון עם סיסמה קצרה ופשוטה, למשל:
- Email: `a@a.com`
- Password: `123`

כעת במסך ההתחברות, ניתן לקבל גישה על ידי הקלדת הבא בתיבת שם המשתמש:
```
' OR 1=1 --
```
המערכת תעקוף את מנגנון האימות ותכניס אתכם ישירות ללא סיסמה — זוהי בדיקת **SQL Injection**.

---

### בדיקת Stored XSS

לאחר התחברות לחשבון, בלוח הבקרה הזינו את הקוד הבא בשדה הוספת לקוח:
```html
<script>alert("Hacked by XSS")</script>
```
לאחר מכן תועברו למסך ההצלחה והקוד ירוץ ויופיע בתור פופ-אפ בדפדפן.

לאחר מכן, עצרו את השרת בטרמינל בעזרת `CTRL+C`.

---

### גרסה מאובטחת

נווטו לגרסה המאובטחת:
```bash
cd Secure_Version
python secure_app.py
```

פתחו את הדפדפן וגשו לכתובת:
```
http://127.0.0.1:5000
```

הירשמו לחשבון חדש — המערכת אוכפת חוקי סיסמה מורכבים המצויים בקובץ `config.json`.

כעת כשננסה להתחבר עם:
```
' OR 1=1 --
```
המערכת תזהה את השורה הזו כטקסט רגיל בזכות **Parameterized Queries**.

כשנריץ את:
```html
<script>alert("Hacked by XSS")</script>
```
במסך הוספת לקוח — הלקוח יתווסף בהצלחה תחת השם הזה ולא יזהה את השורה כקוד אלא כטקסט רגיל.

בנוסף, בגרסה המאובטחת יש מנגנון שכחתי סיסמה על ידי הדמיית שליחת מייל עם טוקן שנוצר על ידי SHA-1.
